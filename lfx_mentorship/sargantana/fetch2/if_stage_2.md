
`if_stage_2` implements Stage F2 of the pipeline. It collects instruction responses from the I-cache, manages pipeline stalls caused by cache misses or downstream backpressure, merges page fault exceptions, and forwards valid instruction packets to the downstream Instruction Queue.

### **Stall Generation & Cache Miss Management**

* Miss Check: Evaluates `stall_o = fetch_i.valid && !(resp_icache_cpu_i.valid || fetch_i.ex.valid || resp_icache_cpu_q.valid)`. If F1 sent a valid PC but no instruction payload or exception is present, `stall_o` goes high to freeze [[if_stage_1|Fetch Stage 1]].

### **Skid Buffer / Response Register**

* Register: `resp_icache_cpu_q` acts as a 1-entry holding register.
* Behavior: If I-cache returns valid data (`resp_icache_cpu_i.valid`) but downstream stages are stalled (`stall_i == 1`), the response is captured into `resp_icache_cpu_q`.
* Selection: `fetch_o.inst` selects buffered data `resp_icache_cpu_q.data` if valid, otherwise passing live cache data `resp_icache_cpu_i.data`. Flush signals (`flush_i`) clear the buffer.

### **Exception Priority Merging**

Cascades exceptions into `fetch_o.ex` using strict priority:

1. Early F1 exceptions passed in `fetch_i.ex.valid` (misaligned PC, address fault).
2. Instruction Page Faults (`INSTR_PAGE_FAULT`) generated by MMU during cache lookup.
3. Instruction Guest Page Faults (`INSTR_GUEST_PAGE_FAULT`). Computes faulting guest address `origin2`.
